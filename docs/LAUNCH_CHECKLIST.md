## Step 2 — Firebase Blaze plan (payment method required — now optional for launch)

Blaze is only needed for the Firebase Cloud Functions path and its stronger
per-user Firestore quota (40 req/day + `ai_proxy_logs`). **The AI coach no

Cloudflare Worker. Blaze remains the upgrade path for server-side quota and
Firestore triggers; the payment method can only be added by the account owner.

## Step 3 — Deploy the AI backend

**Step 3-alt, preferred at launch — Blaze-free Cloudflare Worker** (`sagitta-ai/`, see its README):
~3 minutes, free, no card. `npx wrangler login` → `npx wrangler secret put OPENROUTER_API_KEY`
→ `npx wrangler secret put FIREBASE_PROJECT_ID` (enter `nexus-app-6acc7`) → `npx wrangler deploy`,
then set `AI_PROXY_URL=https://sagitta-ai.<subdomain>.workers.dev/proxyAI` in `local.properties`
and rebuild the AAB. The app routes `proxyAI`, `streamAI`, `deepResearchFn` and `leetcodeStats`
through the Worker. Free-tier reality: OpenRouter caps free models at 50 requests/day per
account (<$10 credits); the app's `AIRateLimiter` (10/day per device) sits under that.

**Firebase path (needs Blaze):**

```bash
cd backend
firebase functions:secrets:set OPENROUTER_API_KEY   # paste the Step-1 key
firebase deploy --only functions
```

Note: the OpenRouter secret was never actually set — Secret Manager access itself
requires Blaze, so `functions:secrets:set` can only run after Step 2.

**Do not apply Android restrictions on the Firebase API key before the first Play
upload.** Play re-signs releases with the App Signing key, so a restriction list
that omits that certificate breaks auth on store builds. Sequence: upload the
AAB → copy the App Signing certificate SHA-1/SHA-256 from Play Console →
Setup → App restrictions with the package `com.nexus.app` plus **all three**
fingerprints (App Signing, this upload key, the debug key from
`~/.android/debug.keystore`). Restricting early is the one move here that can
take a working app offline.

## Play Data Safety — what to enter

Derived from `docs/privacy-policy.html` and the code that actually runs. If a line
here stops matching the code, fix the code or this section, not the form.

| Question | Answer | Where it comes from |
|---|---|---|
| Does the app collect user data? | Yes | `UserPreferences`, Room `nexus.db`, Firestore |
| Account sign-in | Yes — email address, display name | Firebase Auth (email/password + Google) |
| Profile data | Yes — college, year, graduation target, declared skills | Onboarding, `ProfileViewModel` |
| App activity | Yes — saved listings, applications and their status, streak, XP, score history, portfolio entries | Room + `FirestoreSyncWorker` for signed-in accounts |
| In-app messages | Yes — AI chat prompts and answers | `AIChatViewModel` |
| Photos / audio / video, location, contacts, device identifiers | No | nothing collects these |
| Is data encrypted in transit? | Yes | TLS to Firebase and to `SAGITTA_FEED_URL` |
| Can users request data deletion? | Yes | in-app account deletion clears Firestore rows and local stores |
| Is data shared with third parties? | Yes, for two purposes only | (1) AI prompts relayed through our own backend (Cloudflare Worker or Firebase Function) to a model provider — free-tier providers may retain prompts, exactly as the published policy and in-app disclosure state; (2) Firebase Analytics events to Google |
| Advertisements | None | no ad SDK in the dependency graph |
| Other third-party sharing or selling | No | no analytics/attribution SDKs beyond Firebase |
| Is this app for children? | No — target audience 13+ | Play target-audience declaration |
| Safe browsing / data stored on device | Yes — device storage is primary, which is why the app works offline | Room + DataStore, see OFFLINE FIRST in the listing |

Also declare: data is retained while the account exists and is removed on deletion;
the privacy policy URL above is the one Play reviewers will open.

**Prominent disclosure and consent — built, verify against the current policy text.**
The first screen a student sees (`AuthPrivacyNotice` in `feature/auth`) states, above
the buttons that collect anything, that saved listings, applications and progress stay
on the device, that signing in backs them up to the student's own account, that AI
questions are relayed through our own server to a model provider that may retain
free-tier prompts, and that app usage is logged; directly under it is the "By continuing, you agree to our / Privacy
Policy" link to the URL above. The acknowledgement is the continue action itself —
there is no separate checkbox. That is normally accepted, but if a Play reviewer asks
for an explicit tick, add one rather than arguing the form.

If either the policy or the collectors change, edit
`R.string.auth_data_disclosure` in the same commit as the policy, or this screen starts
lying.

## Regular opportunity updates (already built)

- Feed: `SyncWorker` refreshes `feed/opportunities.json` every six hours on
  unmetered network, plus an explicit pull-to-refresh on the feed screens;
  expired deadlines are hidden even offline.
- Notifications: `DailyBriefingWorker` at 07:00, `ProactiveInsightWorker` at
  08:00, `EveningReviewWorker` at 21:00, `StreakWorker` daily, and
  `DeadlineAlertWorker` sweeping every six hours. The deadline sweep watches
  only items the student saved or is already applying to, and warns at a week
  out (4-7 days), at 2-3 days, the day before, the morning of, and after 18:00
  on the closing day. Each warning fires once per opportunity, and at most one
  notification leaves a sweep, so a heavy pipeline cannot become a stack of
  pings. `NewMatchAlertWorker` runs on the same six-hour sweep and says nothing
  unless the refreshed feed actually added a listing that asks for at least one of
  the skills this student declared — with no declared skills, or notifications off,
  it returns without a message. Deadlines in the feed are calendar days, so no
  reminder claims a precision the source never published.
- Telemetry: `WeeklyRetentionWorker` writes one local retention row a week
  (active days plus only those surfaces holding the student's own data);
  `LeetCodeSyncWorker` every 12 h; `FirestoreSyncWorker` for accounts that sign
  in; `CareerMemoryMaintenanceWorker` for local pruning.
- All schedules live in `core/sync/src/main/kotlin/com/nexus/sync/SyncScheduler.kt`.
